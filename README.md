# RohBar — Межгородские грузоперевозки | Боркашонии байнишаҳрӣ

**RohBar** — цифровая платформа для организации межгородских автомобильных грузоперевозок в России с полной локализацией **RU/TG**.

---

# Русский

## Назначение проекта

RohBar объединяет заказчиков, перевозчиков и водителей в единой системе для организации перевозки: от создания заявки и поиска подходящего транспорта до согласования условий, изменения статусов, контроля выполнения и хранения истории заказов.

Проект ориентирован на российский рынок и предназначен для цифровизации межгородских грузоперевозок.

## Возможности платформы

### Заказчик

- регистрация и профиль;
- создание заявки на перевозку;
- указание пунктов погрузки и выгрузки;
- параметры и характеристики груза;
- дата и условия перевозки;
- поиск перевозчиков;
- просмотр предложений;
- согласование условий;
- управление активными и завершёнными заказами;
- просмотр статуса перевозки;
- история заказов.

### Перевозчик

- регистрация и профиль;
- управление автопарком;
- добавление транспорта и его характеристик;
- просмотр и поиск заявок;
- фильтрация по маршрутам и параметрам;
- отклик на заявки;
- управление принятыми перевозками;
- изменение статусов;
- история выполненных перевозок.

### Платформа

- единая система пользователей и ролей;
- управление заявками и заказами;
- маршруты и географические данные;
- уведомления;
- журнал событий;
- административное управление;
- аналитика и статистика;
- локализация RU/TG.

## Направления перевозок

Основной профиль RohBar — **межгородские автомобильные грузоперевозки по России**.

Поддерживаемые сценарии:

- город → город;
- регион → регион;
- склад → склад;
- производство → склад;
- склад → торговая точка;
- прямые междугородние перевозки;
- поиск обратной загрузки для транспорта.

В дальнейшем география и набор направлений могут быть расширены.

## Роли пользователей

| Роль | Назначение |
|---|---|
| **Заказчик** | Создаёт заявки и организует перевозку |
| **Перевозчик** | Находит заявки и выполняет перевозки |
| **Водитель** | Работает с назначенной перевозкой |
| **Администратор** | Управляет пользователями, заявками и системой |

Доступ к данным и операциям определяется ролевой моделью и серверными правилами авторизации.

## Основные функции

### Заявки

Заявка содержит маршрут, груз, требования к транспорту, дату перевозки и дополнительные условия.

### Поиск и подбор

Поиск выполняется по городам отправления и назначения, дате, типу транспорта, типу кузова, характеристикам груза и другим параметрам.

### Жизненный цикл заказа

Базовая модель:

`Создана → На рассмотрении → Принята → В пути → Доставлена → Завершена`

Фактический набор статусов и допустимые переходы определяются бизнес-логикой системы.

### Профили и транспорт

Перевозчик управляет профилем и автопарком. Для транспорта хранятся необходимые характеристики, используемые при подборе заявок.

### Уведомления

Пользователь получает уведомления о новых предложениях, изменениях заказа, назначении перевозки и изменении её статуса.

## Локализация RU/TG

RohBar является двуязычной платформой:

- **RU — русский**;
- **TG — тоҷикӣ / таджикский**.

Локализация охватывает интерфейс, навигацию, формы, статусы, системные сообщения, ошибки, уведомления, справочники и административную часть.

Русский язык ориентирован на основной рынок России, таджикский — на таджикоязычных пользователей платформы.

## Техническая архитектура

Проект строится как модульная клиент-серверная система с разделением frontend, backend, базы данных и внешних интеграций.

```text
┌─────────────────────────────┐
│       Web / Mobile UI       │
│       RU / TG interface     │
└──────────────┬──────────────┘
               │ HTTPS / API
               ▼
┌─────────────────────────────┐
│         Backend API         │
│ auth · roles · business     │
│ requests · orders · fleet   │
└───────┬──────────┬──────────┘
        │          │
        ▼          ▼
┌──────────────┐ ┌────────────────┐
│   Database   │ │ External APIs  │
│ users        │ │ maps / geo     │
│ requests     │ │ notifications  │
│ orders       │ │ integrations   │
│ vehicles     │ └────────────────┘
└──────────────┘
```

Архитектурные принципы:

- API-first;
- разделение ответственности компонентов;
- RBAC и серверная авторизация;
- серверная валидация;
- централизованная бизнес-логика;
- безопасная обработка пользовательских данных;
- журналирование важных операций;
- готовность к горизонтальному масштабированию;
- возможность подключения картографических и других внешних API.

## Требования

Для разработки и запуска потребуются:

Точные версии зависимостей должны фиксироваться непосредственно в конфигурационных файлах проекта после реализации соответствующих компонентов.

Раванди кор аз эҷоди дархост ва ҷустуҷӯи нақлиёт то мувофиқаи шартҳо, тағйири ҳолат, назорат ва нигоҳдории таърихи фармоишҳоро дар бар мегирад.

1. **Соддагӣ** — эҷод ва ҷустуҷӯи интиқол бояд зуд ва фаҳмо бошад.
2. **Эътимоднокӣ** — маълумот ва ҳолатҳои интиқол бояд шаффоф ва назоратшаванда бошанд.
3. **Масштабпазирӣ** — система бояд бе аз нав сохтани асоси худ рушд карда тавонад.
